2.3 COMMUNICATION PROTOCOL SPECIFICATION
2.3.1 Semantic Bus Architecture Using Redis
Core Infrastructure
The Semantic Bus is the central nervous system of the Holy Grail Refinery, implemented as a Redis pub/sub messaging system that enables fully asynchronous, event-driven communication between all 35 agents.

Technology Stack:

Redis 7.x: Primary message broker
Redis Streams: For durable message queues with consumer groups
Redis Pub/Sub: For broadcast notifications
Redis Hashes: For metadata storage
Redis Sorted Sets: For priority queues
Key Characteristics:

Zero Direct Communication: Agents never call each other directly
Decoupling: Publishers don't know subscribers, subscribers don't know publishers
Scalability: Supports horizontal scaling by adding more agent instances
Persistence: Messages can be persisted for audit and replay
Real-Time: Sub-millisecond message delivery
2.3.2 Protocol Specifications
Protocol Alpha: Directive Protocol
Purpose: High-level commands and strategic direction from Executive tier downward

Direction: CEO → Sub-Managers → Specialists

Message Structure:

json
{
  "protocol": "ALPHA",
  "version": "1.0",
  "message_id": "uuid-v4",
  "timestamp": "ISO-8601",
  "sender": "EXEC-002",  // CEO
  "recipients": ["POD-A-MGR", "POD-B-MGR", "POD-C-MGR", "POD-D-MGR"],
  "directive": {
    "type": "MISSION_ASSIGNMENT",
    "priority": "HIGH",  // HIGH | MEDIUM | LOW
    "deadline": "ISO-8601",
    "requirements": {
      "feature_id": "uuid",
      "domain": "list_operations",
      "target_languages": ["python", "javascript", "rust", "java"],
      "quality_threshold": 0.9999,
      "constraints": ["no_external_dependencies", "memory_safe"]
    },
    "context": {
      "user_intent": "Implement efficient list filtering",
      "performance_target": "O(n) time complexity",
      "additional_notes": "Must handle null values gracefully"
    }
  }
}
Redis Channel Pattern: alpha:directive:{recipient_id}

Error Handling:

If recipient unavailable, message persists in Redis Stream
Retry with exponential backoff (1s, 2s, 4s, 8s, 16s max)
After 5 retries, escalate to SRE Agent
Response Expected: Sub-Manager sends acknowledgment within 1 second

## **2.3.4 Protocol Selection Decision Trees**

### **When to Use Each Protocol**
```
START
 │
 ├─> Is this a human-facing message?
 │    └─> YES → Use Protocol OMEGA
 │
 ├─> Is this delivering completed work (LogicNodes)?
 │    └─> YES → Use Protocol BETA
 │
 ├─> Is this a quality verification result?
 │    └─> YES → Use Protocol DELTA
 │
 ├─> Is this a directive or command?
 │    └─> YES → Use Protocol ALPHA
 │
 ├─> Is this broadcasting knowledge/documentation?
 │    └─> YES → Use Protocol SIGMA
 │
 └─> Is this infrastructure/rate-limit management?
      └─> YES → Use Protocol RHO
```

### **Multi-Protocol Scenarios**

**Scenario**: CEO assigns work to Pod A
1. **Protocol ALPHA**: CEO → Sub-Manager (directive)
2. **Protocol ALPHA**: Sub-Manager → Specialists (distribute work)
3. **Protocol BETA**: Specialists → Sub-Manager (deliver LogicNodes)
4. **Protocol DELTA**: Audit Agent → Specialists (verify quality)
5. **Protocol BETA**: Sub-Manager → CEO (aggregate results)

Pattern 1: Semantic Search by Specialist Agent

Execution Flow:

IS Agent receives query from Python Specialist
Generate embedding vector using text-embedding-004
Search Milvus with cosine similarity (top 10 results)

Return top 3 most relevant chunks

SQL + Vector Query:

python
# Step 1: Vector search in Milvus
vector_results = milvus_client.search(
    collection_name="knowledge_vectors",
    query_vectors=[embedding],
    limit=10,
    filter="language == 'python'",
    output_fields=["chunk_id", "doc_id"]
)

# Step 2: Retrieve full content from PostgreSQL
chunk_ids = [r['chunk_id'] for r in vector_results]
sql = """
    SELECT c.chunk_text, d.title, d.source_url, d.library_name
    FROM document_chunks c
    JOIN documents d ON c.doc_id = d.doc_id
    WHERE c.chunk_id = ANY(%s)
    ORDER BY array_position(%s, c.chunk_id)
"""
results = pg_cursor.execute(sql, (chunk_ids, chunk_ids))

        "id": node.id,
        "domain": node.domain,
        "concept": node.concept,
        "full_json": json.dumps(node.to_dict())
    })
    
    # 2. Update indexes
    redis.sadd(f"domain:{node.domain}", node.id)
    redis.sadd(f"language:{node.source_language}", node.id)
    redis.sadd("audit:pending", node.id)
    
    # 3. Add to mission
    redis.lpush(f"mission:{node.mission_id}:nodes", node.id)
    
    # 4. Git commit
    file_path = f"domains/{node.domain}/{node.concept}/{node.source_language}.json"
    write_file(file_path, json.dumps(node.to_dict(), indent=2))
    git_commit(file_path, f"Extract {node.source_language} {node.concept} - confidence {node.confidence}")

3.1.2 Semantic Abstraction Principles
Core Philosophy: Refined-IR captures WHAT a program does, not HOW it does it in a specific language.

Principle 1: Intent Over Implementation
Bad (Too Language-Specific):

json
{
  "concept": "python_list_comprehension",
  "intent": "Use Python's [x for x in list if predicate(x)] syntax"
}
Good (Universal Intent):

json
{
  "concept": "filter",
  "intent": "Select elements from a collection that satisfy a predicate function",
  "inputs": [
    {"name": "collection", "type": {"base": "list"}},
    {"name": "predicate", "type": {"base": "function"}}
  ],
  "outputs": [
    {"name": "filtered_collection", "type": {"base": "list"}}
  ]
}
Principle 2: Explicit Constraints
All assumptions must be stated explicitly as preconditions or constraints.

Example: Array indexing

json
{
  "concept": "array_access",
  "inputs": [
    {
      "name": "array",
      "type": {"base": "list"},
      "constraints": [
        {"type": "non_null"}
      ]
    },
    {
      "name": "index",
      "type": {"base": "integer"},
      "constraints": [
        {"type": "range", "expression": "0 <= index < len(array)"}
      ]
    }
  ],
  "preconditions": [
    {"type": "predicate", "expression": "array is not empty"},
    {"type": "predicate", "expression": "index is within bounds"}
  ],
  "side_effects": []
}
Principle 3: Side Effect Transparency
All side effects must be declared. A function is pure if and only if side_effects is an empty array.

Example: File write (impure)

json
{
  "concept": "file_write",

3.1.5 Type System and Type Inference Rules
Type Compatibility Rules
Rule 1: Subtype Relationship

integer is compatible with float (widening)
float is NOT compatible with integer (narrowing requires explicit cast)

Rule 2: Generic Type Variance

list<integer> is NOT compatible with list<float> (invariant)
function<(float) -> void> is compatible with function<(integer) -> void> (contravariant in parameters)

Rule 3: Option/Result Types

option<T> represents Some(T) or None
result<T, E> represents Ok(T) or Err(E)
