5.2 UI/UX Design System
Design Principles and Philosophy
Core Design Philosophy: "Industrial Clarity"
The Holy Grail Refinery UI embodies the metaphor of a software manufacturing plant. The design language draws from industrial control rooms, mission control centers, and factory floor management systems - professional tools designed for operators who need clarity under pressure.

Guiding Principles:

Principle	Description	Application
Operational Transparency	Every system state is visible at a glance	Dashboard shows all 35 agents with real-time status
Progressive Disclosure	Simple overview first, details on demand	Agent cards expand to show full 7-part profiles
Semantic Over Syntactic	Show meaning, not just code	LogicNodes displayed as intent, not raw JSON
Zero Ambiguity	Critical states are unambiguous	Red/yellow/green status with explicit labels
Audit Trail First	Every action is traceable	Traceability panel visible in all views

### Accessibility (WCAG 2.1 AA) Guidelines

#### Color Contrast Requirements

All text must meet minimum contrast ratios:

| Text Type | Minimum Ratio | Verified Combinations |
|-----------|---------------|----------------------|
| Normal text | 4.5:1 | White on Refinery Navy (12.6:1) ✓ |
| Large text | 3:1 | Circuit Teal on Navy (4.8:1) ✓ |
| UI components | 3:1 | All status colors verified ✓ |

#### Keyboard Navigation

- All interactive elements reachable via Tab
- Focus indicators visible with 2px Circuit Teal outline
- Skip links for main content areas
- Arrow keys navigate within component groups (agent lists, LogicNode trees)

#### Screen Reader Support

- ARIA labels on all interactive elements
- Live regions for real-time status updates
- Semantic HTML structure for agent hierarchies
- Alt text for all visualization components

#### Motion and Animation

- Respect `prefers-reduced-motion` media query
- Status indicators use color + icon, never animation alone
- Progress animations can be paused
- No auto-playing animations that cannot be stopped

State Management Strategy
Global State (Zustand)
Why Zustand: Lightweight, minimal boilerplate, excellent TypeScript support, works well with React Server Components.

Store Definitions:

typescript
// stores/agentStore.ts
interface AgentState {
  agents: Agent[];
  selectedAgentId: string | null;
  filterByPod: string | null;
  filterByStatus: AgentStatus | null;
  
  // Actions
  setSelectedAgent: (id: string) => void;
  updateAgentStatus: (id: string, status: AgentStatus) => void;
  filterAgents: (pod?: string, status?: AgentStatus) => void;
}

// stores/systemStore.ts
interface SystemState {
  overallHealth: number;
  podHealth: Record<PodId, number>;
  busStatus: 'connected' | 'degraded' | 'disconnected';
  activeAlerts: Alert[];
  
  // Actions
  updateHealth: (health: HealthUpdate) => void;
  acknowledgeAlert: (alertId: string) => void;
}

// stores/missionStore.ts
interface MissionState {
  currentMission: Mission | null;
  smeltCyclePhase: SmeltCyclePhase;
  activeTasks: Task[];
  completedLogicNodes: number;
  totalLogicNodes: number;
  
  // Actions
  startMission: (mission: Mission) => void;
  updateProgress: (progress: ProgressUpdate) => void;
  cancelMission: () => void;
}
Server State (TanStack Query)
For data that comes from the backend (agent details, LogicNode registry, etc.):

typescript
// hooks/useAgentProfile.ts
export function useAgentProfile(agentId: string) {
  return useQuery({
    queryKey: ['agent', agentId],
    queryFn: () => fetchAgentProfile(agentId),
    staleTime: 30 * 1000, // 30 seconds
  });
}

// hooks/useLogicNodes.ts
export function useLogicNodes(filters: LogicNodeFilters) {
  return useInfiniteQuery({
    queryKey: ['logicNodes', filters],
    queryFn: ({ pageParam }) => fetchLogicNodes({ ...filters, cursor: pageParam }),
    getNextPageParam: (lastPage) => lastPage.nextCursor,
  });
}
