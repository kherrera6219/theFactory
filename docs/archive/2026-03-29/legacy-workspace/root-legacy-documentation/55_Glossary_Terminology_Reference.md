## 1. CORE CONCEPTS

### 14 → 4 → 1 Model
The Holy Grail Refinery's foundational approach: 14 programming languages are processed by 4 specialized pods, which fuse their understanding into 1 unified semantic representation.

### Agent
An autonomous AI-powered entity within the Holy Grail Refinery system that performs specialized tasks. There are 35 total agents organized into tiers.

### AW1
The local hardware platform (development workstation) where the Holy Grail Refinery runs. Specifications: Intel i7-14700F, RTX 4060 Ti, 32GB RAM, 1TB SSD.

### Concept
A discrete programming pattern or operation (e.g., "filter", "map", "async_await") that can be represented as a LogicNode.

### Confidence Score
A numerical value (0.0 to 1.0) representing the certainty that a LogicNode accurately captures the intent of source code. Specialists aim for ≥0.95 confidence.

### Domain
A category of programming concepts (e.g., "list_operations", "async_programming", "memory_management"). LogicNodes are organized by domain.

### Holy Grail
The ultimate goal: a system that achieves perfect semantic understanding across all programming paradigms, enabling true language-agnostic comprehension.

### Intent
A plain English description of what a piece of code is meant to accomplish, independent of implementation details.

### LogicNode
The universal representation of computational intent in the Holy Grail Refinery. A structured data format capturing inputs, outputs, preconditions, postconditions, and semantic meaning.

### Mission
An end-to-end workflow from user requirements to deliverables. Missions are assigned to the PM Agent and orchestrated through the 35-agent system.

### Paradigm
A programming style category: Dynamic, Systems, Enterprise, or Mathematical. Used to classify languages and LogicNodes.

### Pod
A group of language specialists focused on a single paradigm (Pod A: Dynamic, Pod B: Systems, Pod C: Enterprise, Pod D: Mathematical). Each pod has 6 agents.

### PRD (Product Requirements Document)
A structured document generated by the PM Agent that captures user requirements and mission objectives.

### Refined-IR (Refined Intermediate Representation)
The universal logic representation format used by Holy Grail Refinery. The "IR" in LogicNode design.

### Semantic Bus
The Redis-based publish/subscribe messaging system that enables communication between all 35 agents.

### Vibe
Informal term for the initial user input or request that starts a mission. The PM Agent "captures the vibe" and transforms it into a formal PRD.

### Zero-Dependency Binary
A compiled output that contains all necessary code without external dependencies, enabling standalone execution.

## 2. AGENT TERMINOLOGY

### Agent ID
Unique identifier for an agent following pattern: `[TYPE]-[LANGUAGE/ROLE]-[NUMBER]`  
Examples: `AGENT-PY-001`, `MANAGER-POD-A-001`, `PM-001`, `CEO-001`

### Agent Profile
The 8-part specification defining an agent's role, education, traits, methods, tools, master instruction, protocol communication, and decision framework.

### Agent State
The current operational status of an agent. Standard states: INIT, IDLE, RECEIVING, PROCESSING, COMPLETE, ERROR, PAUSED, SHUTTING_DOWN.

### Agent Tier
The hierarchical level of an agent: Executive (2 agents), Support Ring (9 agents), or Refinery Pods (24 agents).

### Audit Agent
Specialized agent that verifies LogicNodes through equivalence testing with 0.0001% tolerance (999 of 1000 tests must pass).

### CEO Agent (Grand Manager)
The central orchestration agent that receives PRDs from the PM Agent, decomposes work across pods, and performs Grand Fusion of results.

### Context Window
The maximum amount of text (typically measured in tokens) that an LLM-powered agent can process at once. Holy Grail agents use 1M token windows.

### Heartbeat
Regular status message sent by agents to indicate they are operational and responsive.

### Language Specialist
An agent specialized in extracting LogicNodes from source code in a specific programming language (e.g., Python Specialist, JavaScript Specialist).

### Manager Agent
General term for agents that coordinate other agents. Includes CEO Agent and Sub-Managers.

### PM Agent (Project Manager)
The user-facing agent that captures requirements, generates PRDs, and delivers results to users.

### Pod Manager (Sub-Manager)
An agent that coordinates the language specialists within a pod and performs pod-level consolidation.

### State Machine
The finite state machine that governs an agent's lifecycle and valid state transitions.

### Support Agent
One of 9 agents in the Support Ring providing infrastructure services (IS Agent, API Broker, Accountant, Security Agent, etc.).

## 3. TECHNICAL TERMS

### AST (Abstract Syntax Tree)
A tree representation of source code structure used by language specialists to analyze and extract patterns.

### Context Caching
A technique for reusing LLM context across multiple requests to reduce token consumption and cost. Achieves ~90% cost reduction.

### Docker Container
An isolated runtime environment for a single agent, providing resource isolation and consistent deployment.

### Equivalence Testing
The verification process where Audit Agents run 1,000 tests per LogicNode to ensure semantic correctness.

### FSM (Finite State Machine)
The formal model used to manage agent lifecycle states and transitions.

### LangGraph
The workflow orchestration framework used to coordinate multi-agent interactions and state management.

### MCP (Model Context Protocol)
Protocol for integrating external services and data sources with LLM agents.

### Milvus
The vector database used for semantic search in the Knowledge Lake.

### PostgreSQL
The primary relational database for structured data (State Graph, LogicNode Registry, Traceability Ledger).

### Redis
The in-memory data store used for the Semantic Bus (pub/sub messaging) and caching.

### Semantic Search
Vector-based search technique used in the Knowledge Lake to find relevant documentation based on conceptual similarity.

### Token
The unit of text processing for LLMs. One token ≈ 0.75 words or 4 characters. Used for cost calculation and context window limits.

### Vector Embedding
High-dimensional numerical representation of text used for semantic search.

## 4. PROTOCOL & COMMUNICATION

### Protocol Alpha
Communication protocol between PM Agent and CEO Agent for mission management.

### Protocol Beta
Communication protocol between CEO Agent and Pod Sub-Managers for work distribution.

### Protocol Delta
Communication protocol from Language Specialists to Audit Agents for verification requests.

### Protocol Sigma
Communication protocol between agents and the IS Agent (Knowledge Lake) for documentation queries.

### Protocol Omega
Communication protocol between CEO Agent and Support Ring agents for infrastructure requests.

### Protocol Rho
Communication protocol between Mission Control UI and PM Agent for user interactions.

### Message Type
The specific kind of message within a protocol (e.g., "task_assignment", "task_complete", "status_request").

### Correlation ID
An identifier that links related messages together, typically a mission_id or task_id.

### In Reply To
Message field that references the message_id being responded to, creating message chains.

### Payload
The main content of a message, containing the actual data being communicated.

### Pub/Sub (Publish/Subscribe)
The messaging pattern used by the Semantic Bus where agents publish messages to channels and subscribe to receive them.

## 6. DOMAIN-SPECIFIC TERMS

### Async Programming
Domain covering asynchronous execution patterns: async/await, promises, futures, coroutines, event loops.

### Concurrency
Domain covering parallel execution: threads, locks, mutexes, semaphores, race conditions.

### Data Structures
Domain covering collections and containers: lists, arrays, maps, sets, trees, graphs.

### Error Handling
Domain covering exception management: try/catch, error propagation, panic/recover, result types.

### IO Operations
Domain covering input/output: file operations, network requests, streams, buffers.

### List Operations
Domain covering collection transformations: filter, map, reduce, sort, group.

### Memory Management
Domain covering resource allocation: malloc/free, RAII, ownership, garbage collection, reference counting.

### String Operations
Domain covering text manipulation: concatenation, splitting, parsing, formatting, regex.

### Type Systems
Domain covering type definitions: primitives, composites, generics, constraints, inference.

## 7. PROGRAMMING LANGUAGE TERMS

### Borrowing
Rust concept where references to data are temporarily loaned without transferring ownership.

### Closure
A function that captures variables from its surrounding scope.

### Comptime
Zig feature for compile-time code execution and metaprogramming.

### Decorator
Python pattern for modifying function/class behavior using @decorator syntax.

### Duck Typing
Dynamic typing approach where object capabilities matter more than explicit type declarations.

### Extension Method
C# feature allowing addition of methods to existing types without modification.

### Generator
Function that yields values lazily using yield keyword (Python, JavaScript).

### Higher-Order Function
Function that takes functions as arguments or returns functions.

### Inline Assembly
Low-level code embedding assembly instructions directly in source code (C, C++, Rust).

### LINQ (Language Integrated Query)
C# feature for SQL-like queries on collections.

### Macro
Metaprogramming feature for code generation (Rust, C/C++, Julia).

### Monad
Functional programming pattern for chaining operations (common in Scala).

### Null Safety
Type system feature preventing null reference errors (Kotlin, Swift).

### RAII (Resource Acquisition Is Initialization)
C++ pattern where resource lifetime is tied to object lifetime.

### Tail Call Optimization
Compiler optimization for recursive functions to avoid stack overflow.

### Trait
Rust/Scala concept similar to interfaces defining shared behavior.

### Type Inference
Compiler's ability to deduce types without explicit annotations.

### Unsafe Block
Code section that bypasses language safety guarantees (Rust, Zig).

## 8. INFRASTRUCTURE TERMS

### Blue-Green Deployment
Deployment strategy with two identical environments for zero-downtime updates.

### Circuit Breaker
Pattern that prevents cascading failures by stopping requests to failing services.

### Container Orchestration
Management of multiple containers (scheduling, scaling, networking). LangGraph provides this for HGR.

### Hot Reload
Ability to update running code without restart.

### Load Balancing
Distribution of work across multiple agents/services.

### Observability
Ability to understand system internal state through logs, metrics, and traces.

### Rate Limiting
Restriction on API request frequency to prevent abuse/overload.

### Service Mesh
Infrastructure layer for service-to-service communication (not used; Semantic Bus fulfills this role).

### Sidecar Pattern
Architectural pattern where helper process runs alongside main service (not used in HGR).

## 9. QUALITY & TESTING TERMS

### 0.0001% Tolerance
The Holy Grail Refinery's verification standard: LogicNodes must pass 999 of 1,000 equivalence tests.

### Code Coverage
Percentage of code executed during testing. HGR target: ≥90%.

### Edge Case
Unusual or extreme input that tests boundary conditions.

### Equivalence Test
Test verifying that two different implementations produce identical results.

### Flaky Test
Test that sometimes passes and sometimes fails without code changes.

### Integration Test
Test verifying that multiple components work together correctly.

### Mock
Test double that simulates external dependencies.

### Regression Test
Test ensuring previously fixed bugs don't reappear.

### Smoke Test
Quick test suite verifying basic functionality after deployment.

### Unit Test
Test verifying a single component in isolation.
