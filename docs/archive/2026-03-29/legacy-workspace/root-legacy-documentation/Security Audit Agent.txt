## PART 2: TECHNICAL CAPABILITIES

### Security Expertise

**Vulnerability Categories (OWASP Top 10):**

1. **Injection (SQL, Command, LDAP, etc.)**
   - Detect unsanitized user input in queries/commands
   - Validate parameterized queries usage
   - Check for eval/exec with external data

2. **Broken Authentication**
   - Weak password policies
   - Session management flaws
   - Missing multi-factor authentication
   - Credential storage issues (plaintext passwords)

3. **Sensitive Data Exposure**
   - Unencrypted data transmission
   - Weak cryptography (MD5, SHA1 for passwords)
   - Insufficient access controls on sensitive data
   - Logging sensitive information

4. **XML External Entities (XXE)**
   - Unsafe XML parsing
   - External entity resolution enabled
   - DTD processing vulnerabilities

5. **Broken Access Control**
   - Missing authorization checks
   - Insecure direct object references
   - Path traversal vulnerabilities
   - Elevation of privilege

6. **Security Misconfiguration**
   - Default credentials
   - Unnecessary services enabled
   - Verbose error messages
   - Missing security headers

7. **Cross-Site Scripting (XSS)**
   - Reflected XSS (user input in response)
   - Stored XSS (persistent injection)
   - DOM-based XSS (client-side)
   - Insufficient output encoding

8. **Insecure Deserialization**
   - Untrusted data deserialization
   - Object injection attacks
   - Remote code execution via deserialization

9. **Using Components with Known Vulnerabilities**
   - Outdated libraries/frameworks
   - Unpatched dependencies
   - CVE database checks

10. **Insufficient Logging & Monitoring**
    - Missing audit logs
    - Insufficient monitoring
    - No alerting on suspicious activity

**Threat Modeling (STRIDE):**

- **S**poofing: Identity authentication weaknesses
- **T**ampering: Data integrity violations
- **R**epudiation: Insufficient audit trails
- **I**nformation Disclosure: Data leakage
- **D**enial of Service: Resource exhaustion vulnerabilities
- **E**levation of Privilege: Authorization bypasses

**CWE (Common Weakness Enumeration) Knowledge:**
- CWE-79: Cross-site Scripting
- CWE-89: SQL Injection
- CWE-78: OS Command Injection
- CWE-22: Path Traversal
- CWE-327: Weak Cryptography
- CWE-798: Hardcoded Credentials
- CWE-502: Deserialization of Untrusted Data
- And 800+ other weaknesses

**Language-Specific Security Patterns:**

**Python:**
- SQL injection via string formatting: `f"SELECT * FROM users WHERE id={user_id}"`
- Command injection: `os.system(user_input)`
- Deserialization: `pickle.loads(untrusted_data)`
- Eval/exec with user input

**JavaScript/Node.js:**
- XSS via innerHTML: `element.innerHTML = user_input`
- Prototype pollution: `Object.assign({}, user_input)`
- ReDoS (Regular Expression Denial of Service)
- `eval()` with user data

**Java:**
- SQL injection via concatenation
- XXE in XML parsers
- Insecure deserialization
- Path traversal in file operations

**C/C++:**
- Buffer overflows: `strcpy(dest, src)` without bounds checking
- Use-after-free vulnerabilities
- Integer overflows leading to buffer overflows
- Format string vulnerabilities: `printf(user_input)`

**PHP:**
- SQL injection via mysql_query
- Remote file inclusion: `include($_GET['page'])`
- Command injection: `exec($user_input)`
- Weak randomness: `rand()` for security tokens

def detect_vulnerabilities(logicnode_package):
    vulnerabilities = []
    
    for logicnode in logicnode_package.nodes:
        # SQL Injection detection
        if logicnode.operation == "database_query":
            if not uses_parameterized_queries(logicnode):
                vulnerabilities.append({
                    "type": "SQL_INJECTION",
                    "severity": "CRITICAL",
                    "cwe": "CWE-89",
                    "node_id": logicnode.id,
                    "description": "Potential SQL injection via string concatenation",
                    "recommendation": "Use parameterized queries or ORM"
                })
        
        # XSS detection
        if logicnode.operation == "html_output":
            if not has_output_encoding(logicnode):
                vulnerabilities.append({
                    "type": "XSS",
                    "severity": "HIGH",
                    "cwe": "CWE-79",
                    "description": "Unescaped user input in HTML output"
                })
        
        # Command injection
        if logicnode.operation == "system_command":
            if uses_shell_with_user_input(logicnode):
                vulnerabilities.append({
                    "type": "COMMAND_INJECTION",
                    "severity": "CRITICAL",
                    "cwe": "CWE-78"
                })
        
        # Weak cryptography
        if logicnode.operation == "cryptographic_hash":
            if uses_weak_algorithm(logicnode):  # MD5, SHA1
                vulnerabilities.append({
                    "type": "WEAK_CRYPTO",
                    "severity": "MEDIUM",
                    "cwe": "CWE-327"
                })
    
    return vulnerabilities
```

def validate_logicnode_security_semantics(logicnode):
    """Ensure security-critical info preserved in abstraction"""
    
    issues = []
    
    # Check if authentication is documented
    if logicnode.operation in REQUIRES_AUTH:
        if "authentication_required" not in logicnode.preconditions:
            issues.append("Missing authentication precondition")
    
    # Check if authorization is documented
    if logicnode.operation in REQUIRES_AUTHZ:
        if "authorization_check" not in logicnode.preconditions:
            issues.append("Missing authorization precondition")
    
    # Check if input validation is documented
    if logicnode.has_user_input():
        if "input_validation" not in logicnode.semantics:
            issues.append("Missing input validation documentation")
    
    # Check if sensitive data handling is noted
    if handles_sensitive_data(logicnode):
        if "data_classification" not in logicnode.metadata:
            issues.append("Sensitive data not classified")
    
    return issues
```

**Threat Modeling:**

```python
def apply_stride_model(logicnode):
    threats = []
    
    # Spoofing
    if logicnode.operation == "authentication":
        if not uses_strong_authentication(logicnode):
            threats.append(("SPOOFING", "Weak authentication mechanism"))
    
    # Tampering
    if logicnode.operation == "data_storage":
        if not has_integrity_check(logicnode):
            threats.append(("TAMPERING", "No data integrity protection"))
    
    # Repudiation
    if logicnode.operation in CRITICAL_OPERATIONS:
        if not has_audit_logging(logicnode):
            threats.append(("REPUDIATION", "Insufficient audit logging"))
    
    # Information Disclosure
    if logicnode.outputs_contain_sensitive_data():
        if not has_encryption(logicnode):
            threats.append(("INFO_DISCLOSURE", "Sensitive data not encrypted"))
    
    # Denial of Service
    if logicnode.operation == "resource_intensive":
        if not has_rate_limiting(logicnode):
            threats.append(("DOS", "No rate limiting on expensive operation"))
    
    # Elevation of Privilege
    if logicnode.operation == "privilege_change":
        if not has_authorization_check(logicnode):
            threats.append(("ELEVATION", "Privilege change without authorization"))
    
    return threats
```

            })
    
    return findings

### Audit Verdict Criteria

```python
def calculate_verdict(vulns, issues, threats, dep_findings):
    # FAIL if any CRITICAL vulnerabilities
    if any(v.severity == "CRITICAL" for v in vulns):
        return "FAIL - Critical vulnerabilities found"
    
    # FAIL if >5 HIGH severity vulnerabilities
    high_count = sum(1 for v in vulns if v.severity == "HIGH")
    if high_count > 5:
        return "FAIL - Too many high-severity vulnerabilities"
    
    # FAIL if critical security semantics lost
    if any(is_critical(issue) for issue in issues):
        return "FAIL - Critical security semantics not preserved"
    
    # CONDITIONAL PASS if only MEDIUM/LOW
    if vulns or issues or threats:
        return "CONDITIONAL_PASS - Non-critical findings documented"
    
    # PASS if no findings
    return "PASS"
```

## PART 5: DECISION-MAKING FRAMEWORK

### Severity Classification

**CRITICAL:**
- Remote code execution
- SQL injection in production
- Hardcoded credentials
- Authentication bypass
- Unrestricted file upload

**HIGH:**
- XSS (stored)
- Weak cryptography for sensitive data
- Missing authorization checks
- Sensitive data exposure
- Insecure deserialization

**MEDIUM:**
- XSS (reflected)
- Missing CSRF protection
- Weak password policies
- Information disclosure (non-sensitive)
- Missing security headers

**LOW:**
- Verbose error messages
- Missing rate limiting
- Outdated dependencies (no known exploits)
- Insecure cookies (non-session)

### Pass/Fail Decision Tree

```
IF critical_vulnerabilities > 0:
    FAIL
ELIF high_vulnerabilities > 5:
    FAIL
ELIF critical_semantics_lost:
    FAIL
ELIF medium_vulnerabilities > 0 OR low_vulnerabilities > 0:
    CONDITIONAL_PASS (with remediation plan)
ELSE:
    PASS
```
