# Privacy Policy — theFactory (HolyGrail Multi-Agent Software Refinery)

Document version: 2026.03.29  
Last updated: 2026-03-29  
Status: Draft; legal review required  
Audience: Operators, maintainers, legal reviewers, and compliance reviewers

## 1. Overview

theFactory is an enterprise operator platform for AI-assisted software refinery.
This document describes how theFactory handles data collected and processed by its services.

This policy applies to:
- Operators running theFactory on self-hosted infrastructure
- Developers contributing to the open-source codebase
- Any entity integrating with the theFactory API

---

## 2. Data Collected and Processed

### 2.1 Mission Data
When a mission is submitted, theFactory stores:

| Data field | Purpose | Retention |
|------------|---------|-----------|
| `mission_id` | Unique identifier for tracking | Until mission is purged |
| `prompt` | User-supplied task description | Stored in PostgreSQL; configurable retention |
| `requested_target_language` | Routing metadata | With mission record |
| `state` + `event history` | Audit trail of state transitions | Configurable via `OBJECT_STORAGE_RETENTION_DAYS` |
| `metadata_json` | Operator-supplied context | With mission record |

**Sensitive content:** The `prompt` field may contain business logic, code snippets, or
other confidential information.  Operators are responsible for classifying and protecting
this data per their own policies.

### 2.2 Agent Telemetry
Agent heartbeats (`agent_id`, `state`, `queue_depth`) are stored in PostgreSQL and
optionally streamed to the configured observability stack.

### 2.3 LLM Provider Data
Mission prompts are sent to configured LLM providers (OpenAI, Anthropic, Google Gemini)
for agent delegation decisions.  **Only routing-relevant context fields** are included in
LLM API calls (see `_safe_context_json` in `llm_delegation.py`); the raw mission prompt
and source code are never forwarded to LLM providers.

Operators are responsible for reviewing the data processing agreements of each configured
LLM provider.

### 2.4 Vault / Secret Data
LLM provider API keys stored in theFactory Vault are:
- Encrypted at the storage layer (Hashicorp Vault in production)
- Never logged or included in audit artifacts
- Never forwarded to LLM providers or external services

### 2.5 Audit Artifacts
Audit reports generated by the audit-worker are stored in:
- PostgreSQL (summary)
- S3-compatible object storage (full artifact, if `OBJECT_STORAGE_ENABLED=true`)

Artifacts may contain code snippets and mission output.  Apply appropriate access controls.

## 3. Data Retention

| Data category | Default retention | Configurable via |
|---------------|-------------------|-----------------|
| Mission records | Until manually deleted | Database admin |
| Mission events | Until manually deleted | Database admin |
| Audit artifacts (S3) | 90 days | `OBJECT_STORAGE_RETENTION_DAYS` |
| Legal hold (failed missions) | Indefinite until released | `OBJECT_STORAGE_LEGAL_HOLD_ON_FAIL` |
| Redis streams | Rolling window | `MAX_STREAM_LEN` |

---

## 4. Data Sharing

theFactory does **not** share operator data with third parties except:
1. **LLM Providers** — routing context only (see §2.3)
2. **Operator-configured integrations** — any external service configured by the operator (e.g. Qdrant, Neo4j, MinIO) receives data as configured by the operator

---

## 5. Security

Security controls applied to all data:
- TLS in transit for all service-to-service communication
- At-rest encryption for PostgreSQL (operator-managed filesystem encryption)
- API key RBAC with no hardcoded defaults (see `SECURITY.md`)
- All containers run as non-root (`appuser`, uid 10001)
- Prompt injection mitigations applied before LLM forwarding

See [SECURITY.md](../SECURITY.md) for the full security controls reference.

---

## 6. Operator Responsibilities

As a self-hosted platform, **the operator assumes full data controller responsibility**:

- Configuring appropriate access controls on all services and databases
- Applying filesystem/disk encryption on all persistence volumes
- Ensuring LLM provider DPAs cover the data types submitted
- Defining and enforcing their own data retention and deletion policies
- Reporting data breaches per applicable regulations (GDPR Art. 33, CCPA §1798.82, etc.)

## 7. Compliance Mappings

| Regulation | Relevant control |
|------------|-----------------|
| GDPR Art. 25 (Privacy by Design) | Allowlist-filtered LLM context; no raw PII in LLM calls |
| GDPR Art. 32 (Security of Processing) | TLS, RBAC, non-root containers, encrypted vault |
| GDPR Art. 17 (Right to Erasure) | Operator must implement via DB admin / S3 lifecycle |
| SOC 2 CC6 (Logical Access) | API key RBAC, vault key isolation, no hardcoded creds |
| SOC 2 CC7 (System Operations) | HEALTHCHECK, structured logging, alerting endpoints |
| OWASP Top 10 | Input validation, auth on all endpoints, prompt injection hardening |

For a detailed evidence mapping, see [COMPLIANCE_EVIDENCE_MAPPING.md](COMPLIANCE_EVIDENCE_MAPPING.md).
